**Findings**
1. `schema_version` を v1 に据え置きつつ「breaking なし」とする主張は成立していません。[ADR-017 §4](/home/bacon/engawacad/docs/decisions/017-phase10-sketch-curves-and-edits.md:129) は migration hook 不要としますが、[ADR-015 §3](/home/bacon/engawacad/docs/decisions/015-phase9-design-foundations.md:66) と現行 loader は「wire format が breaking に変わるなら version を上げる」契約です。[document.rs](/home/bacon/engawacad/crates/engawa-format/src/document.rs:24) [from_yaml](/home/bacon/engawacad/crates/engawa-format/src/document.rs:72) の挙動上、旧バイナリは `schema_version: 1` のまま新しい `kind: circle` や `SketchTrim` を受け取り、version gate ではなく深い deserialize 失敗で落ちます。これは「旧文書を新実装が読める」だけの片方向互換であり、ADR が書いている「breaking なし」とは別物です。

2. Conic を `coeffs: [f64; 5]` かつ `F = -1` 正規化で表す案は、「一般二次形式」を名乗りながら一般形を表現できていません。[ADR-017 §1](/home/bacon/engawacad/docs/decisions/017-phase10-sketch-curves-and-edits.md:49) の定義では `F=0` の conic を全て落とします。典型例として放物線 `y = x^2` は `x^2 - y = 0` で `F=0` なので、非零スカラー倍では絶対に `F=-1` にできません。退化判定以前に、正当な非退化 conic を入力できない時点で Option A のパラメータ表現は欠陥です。

3. 編集 API の主キーに `sketch_ref: EntityRef` を置く設計は、現行の参照体系と型レベルで衝突しています。[ADR-017 §3](/home/bacon/engawacad/docs/decisions/017-phase10-sketch-curves-and-edits.md:85) に対し、`EntityRef` は現状 `Face / Edge / Vertex` 専用であり、Sketch を表す kind がありません。[EntityKind](/home/bacon/engawacad/crates/engawa-format/src/feature.rs:7) [EntityRef](/home/bacon/engawacad/crates/engawa-format/src/feature.rs:27) [PlaneRef の用途](/home/bacon/engawacad/crates/engawa-format/src/feature.rs:254) からも、これを sketch feature 参照へ流用する余地は示されていません。つまり Trim/Extend/Mirror の対象そのものをこの型で表現できず、採用案の API は入口で破綻しています。

4. `{a}_split_{n}` という派生 ID 規則は、ADR-005 の決定性要件と整合しません。[ADR-017 §3](/home/bacon/engawacad/docs/decisions/017-phase10-sketch-curves-and-edits.md:93) は split ordinal を決定的と主張しますが、[ADR-005](/home/bacon/engawacad/docs/decisions/005-topological-naming.md:147) は生成順カウンタ依存を禁じ、[stable id 契約](/home/bacon/engawacad/docs/decisions/005-topological-naming.md:186) は再生成・再読込で不変であることを求めています。途中に別の trim を挿入しただけで後続の `_split_1/_split_2` が総崩れするので、下流 feature の参照は幾何意図が不変でも壊れます。これは「意味的に同一なら同 ID」を守る案ではなく、履歴位置に依存した再採番です。

5. `Rectangle / Polygon / Slot` を原子的 `SketchElement` として保持しつつ、内部では `Line/Arc` 群へ分解する方針は、押出命名規約と編集粒度の両方を未定義にします。[ADR-017 §1](/home/bacon/engawacad/docs/decisions/017-phase10-sketch-curves-and-edits.md:50) [実装順](/home/bacon/engawacad/docs/decisions/017-phase10-sketch-curves-and-edits.md:181) に対し、[ADR-005](/home/bacon/engawacad/docs/decisions/005-topological-naming.md:170) は押出側面を `side_<sketch要素安定名>` で命名し、[stable id 契約](/home/bacon/engawacad/docs/decisions/005-topological-naming.md:186) は sketch element id の不変性を要求しています。矩形 1 要素から 4 辺・4 角が生まれるのに、どの sub-edge / sub-vertex が stable にどう命名されるかが無く、Trim/Fillet/Chamfer の対象粒度も決まりません。さらに [ADR-010](/home/bacon/engawacad/docs/decisions/010-sketch-input-model.md:16) は `profile` を閉ループ押出プロファイルとして扱っており、現行 build でも単独 Arc を押出可能としてしまっています。[validate_profile_closed](/home/bacon/engawacad/crates/engawa-build/src/lib.rs:551) [arc acceptance](/home/bacon/engawacad/crates/engawa-build/tests/sketch_element_acceptance.rs:56) この曖昧さを抱えたまま曲線種だけ増やすのは危険です。

この ADR は細部調整で救える状態ではありません。`schema_version` の契約違反、Conic 表現の数学的欠陥、`sketch_ref: EntityRef` という不表現な API、履歴挿入で壊れる `_split_n` 命名、そして複合プリミティブの sub-element 安定名未定義が同時に残っています。いずれも採用後に実装 Issue 側で吸収できる「詰め漏れ」ではなく、Decision 自体の前提を崩す構造問題です。少なくとも `SketchRef` と `Wire/Loop` モデルの分離、Conic の再定義、schema bump 方針、編集後 ID の由来規則を先に作り直さない限り、この ADR を foundation として子 Issue を切るのは危険です。
verdict: refuted
